## 1. Confirmed Limitations & Defect Disclosures

### 1.1 Power BI Desktop Environment Smoke Acceptance (Level G4)
- **Limitation**: `PBIDesktop.exe` is not installed on the current host development environment.
- **Impact**: While Power BI Project files (`.pbip`), Semantic Model TMDLs (`.tmdl`), and PBIR report definitions (`report.json`) pass all structural, schema, syntax, cross-reference, and relationship checks (Levels G0–G3), actual binary launch and visual rendering inside Power BI Desktop cannot be validated automatically on this machine.
- **Mitigation / Grounding**: BIOS truthfully marks Level G4 as `UNVERIFIED (PBIDesktop.exe not found on host)` and outputs overall validation status `VALID_WITH_UNVERIFIED_DESKTOP`. BIOS does not fake or fabricate desktop test passes.
- **Recommended Action**: Validate generated `.pbip` projects on a Windows workstation equipped with Power BI Desktop (November 2024 / Fabric release).

### 1.2 Local LLM Inference Latency & Cold-Start Variance
- **Limitation**: When local Ollama with `qwen3.5:4b` is active, initial cold-start invocation exhibits latency overhead (~2–4 seconds) compared to warm inference (~400–800ms) or instantaneous deterministic execution (<50ms).
- **Impact**: Multi-agent workflows with 3 LLM-assisted steps (Intent, KPI Intelligence, Decision) experience cumulative response times of 3–5 seconds under local CPU inference.
- **Mitigation**: Deterministic fallback adapters ensure that if Ollama is offline or times out, BIOS immediately falls back to deterministic rule-based orchestration with zero loss of governance enforcement.
- **Recommended Action**: Warm up Ollama in a background daemon before live demonstrations, or run in deterministic mode for instant responses.

### 1.3 Claude and Gemini Cloud Adapters Are Standby Architecture
- **Limitation**: The repository includes adapter architectures for Claude (`AnthropicAdapter`) and Gemini (`GeminiAdapter`), but these are not configured with live API credentials.
- **Impact**: Cloud LLM inference is currently in standby mode; BIOS relies entirely on local Ollama or deterministic fallback.
- **Mitigation**: Confirms zero external cloud API dependencies and zero paid API costs for hackathon evaluation.
- **Recommended Action**: Enable paid API keys only when enterprise deployment and credential management are established.

### 1.4 Dataset Scope & Synthetic Boundary
- **Limitation**: The underlying dataset (`Bayer_Pharmaceuticals_SinceAI_2026_FINAL_Builder_Data_Pack.xlsx`) is entirely synthetic data generated by SinceAI for the hackathon challenge.
- **Impact**: Real pharma commercial dynamics, patient journeys, and actual Bayer internal financials are not present. Findings, scores, and recommendations reflect the synthetic dataset's deliberate defect patterns and reference signals.
- **Mitigation**: Explicit provenance notice documented in `README.md` and `docs/DATA_DICTIONARY.md`.

## 2. Incomplete Security Controls & Production Roadmap

### 2.1 Enterprise Single Sign-On (SSO) & IdP Integration
- **Current State**: Backend role-based access control (RBAC) is implemented and enforced in FastAPI dependencies and approval service classes (`UserRole` enums: `BI_GOVERNANCE_REVIEWER`, `DOMAIN_STEWARD`, `ASSET_OWNER`, `BIOS_ADMIN`, `REQUESTER`).
- **Limitation**: Production enterprise SSO (e.g. Microsoft Entra ID / Okta SAML/OIDC) is not yet wired to an external identity provider. User roles are currently passed via authenticated request contexts and API headers.
- **Risk**: Without an external IdP, user identity assertions rely on gateway-level security.
- **Milestone 5.6 Priority**: Wire Microsoft Entra ID OAuth2 / JWT bearer token validation into FastAPI middleware.

### 2.2 Report Internal Metadata Metadata Granularity
- **Limitation**: The synthetic workbook provides metadata at the asset level (asset_id, name, workspace, model, audience, endorsement, mapped KPIs). It does not contain internal report visual layouts, embedded DAX expressions, or table partition scripts of legacy reports.
- **Impact**: Duplication intelligence operates across structural semantic models, mapped canonical KPIs, and metadata scopes. It does not perform pixel-level visual diffing or abstract syntax tree (AST) comparisons of legacy DAX formulas.
- **Mitigation**: BIOS explicitly discloses `layers_used` in duplication findings and distinguishes metadata candidate similarity from proven internal report duplication.
